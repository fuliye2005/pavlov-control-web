# 全动作模型理解与收音窗口 0.38.1

2026-11-05实机ESP0.38.1 / STM0.6.6，上层通过Wi-Fi安装并确认。此文优先于0.37.1之前的本地快速动作分流说明。

## 动作理解

所有身体动作语音（单词口令、自然单句、连续动作、停止及重复请求）都进入模型，本地不再调用voice_intent_local或voice_sequence_parse来决定或分流动作。HTTP/蓝牙的直接控制接口不变；模式/计时/偏好/记忆等既有本地服务仍保留。

模型输出需包含requested布尔值，区分明确动作要求与聊天自主表达；本地仍检查否定/讨论、动作白名单、次数/速度/幅度及连续计划边界。requested缺失或格式不合法时拒绝，最多一次带格式纠正提示的重新规划；不是自动重发硬件动作。两次不合法会说明未执行，而不静默误做。

连续计划最多6步、预计30秒，逐步等待控制器完成。网页/蓝牙停止取消剩余步骤。语音停止也经过模型，且不支持处理期间实时插话；不能把它当作全双工急停。

## 收音参数

- 空闲等待开口15秒，替代原约3秒无声即结束；无声超时后的普通轮次间隔约20毫秒。
- 单句最长15秒，缓冲容量512000字节（16kHz、16位单声道）。
- 句尾静音判定1.5秒，预留约0.5秒开头；提交前裁掉多余句尾静音，只保留约0.3秒，避免延长等待又增加无用上传量。
- 首次收听在招呼前做一次约0.4秒背景采样，之后复用并更新噪声底值，避免每轮重新忽略起音。
- 上传、模型思考、播音和动作执行期间仍非持续录音；播放后仍有短暂回声等待。不是本地唤醒，也不是全双工语音。

GET /api/v1/dialog/state 新字段：motion_understanding="model"、model_motion_modifiers=true、local_motion_modifiers=false、listening_wait_seconds=15、max_utterance_seconds=15、speech_end_silence_ms=1500、continuous_capture_while_processing=false。preparing_microphone阶段建议前端显示“准备收音”。

command_sequence字段沿用VOICE-PLANNING.md：source应为model（或尚无计划none）；actions/steps结束后只是历史摘要，不表示仍排队。last_llm_invalid_reason/provider_error_code等为历史诊断，可能在重试恢复后保留，不能仅凭其非空就显示“当前失败”；需结合当前stage/last_error和请求结果。

## 测试与限制

37项实际C模型计划校验、12项实际收音/准备函数体（模拟codec和时钟）检查通过。后者覆盖晚于3秒开口、即时短词、1秒句中停顿、12秒长句、15秒上限、取消和裁静音，不是实际麦克风全环境验收。

24项设备真实模型文本诊断通过，单动作和连续动作逐条确认llm_ok增加、local=false，诊断没有录音/播音/舵机动作。共出现5次格式校验重试，均恢复，未恢复的规划失败计数0；不是长期100%成功率承诺。0.38.0测试第三项曾失败，记录保留，不计成功。

真人实物：仅说“握手”被完整识别，模型选择一次normal/100握手、控制器完成，用户确认握手正常、尾巴不动。随后按提示在“先摇尾巴”和“然后握手”间停约1秒，设备识别为同一句，模型计划wag→handshake并完成，用户确认小狗顺利执行。这两项通过不代替所有语句、噪声、长距离和长时运行测试。

ASR上传偶发延迟/漏收仍需持续观察，不把动作理解统一模型等同于所有语音问题已消除。“巴甫洛夫”本地唤醒模型仍未接入。
