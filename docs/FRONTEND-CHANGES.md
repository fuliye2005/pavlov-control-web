# 前端改版交付说明（2026-11-05）

基于仓库最新提交 `a968627`（ESP0.37.1 / STM0.6.6，新增 `command_sequence`）。只修改 `control.html`，C/H 文件未改动；接口路径、请求体、轮询与超时逻辑均保持原样。

## 修改清单

### 跟进上游更新（VOICE-PLANNING.md）
1. 新增「连续动作」卡片，读取 `dialog/state.command_sequence`：
   - 运行中显示“正在做第 completed+1 / total 步”，逐步标记已完成、当前和待做；
   - 结束后按 result 显示：finished（已按顺序输出完成，实物效果以观察为准）、dry_run（诊断演练，未驱动舵机，不标记完成）、invalid、rest_blocked、cancelled（已完成几步，剩余几步取消）、aborted（第几步未完成，剩余终止）；
   - 显示来源：本地解析 / 模型规划·设备已校验；每步显示次数和快慢参数；
   - 结束后的列表明确是“上一组”摘要，不当作仍在排队。
2. 狗脸联动：连续动作进行时，标题显示“连续动作 x/y”，副标题显示当前动作；点鼻子的状态卡也显示连续动作进度。
3. 帮助文案：一句话可以说多个动作（最多 6 个、约 30 秒）；单说“前进”“左转”等不必先叫名字（`locomotion_requires_name=false`）。
4. 停止：上游已让 `motion/stop` 与 `dialog/control stop` 一样结束剩余步骤，卡片写明“点停止会取消剩余步骤”。前端停止按钮的请求没有改动。

### 信息架构与视觉（改版方案）
5. 常驻顶栏：名字、连接状态、停止按钮；操作提示固定在顶栏下方，滑到任何位置都看得见。
6. 分为 4 个分区：控制 / 互动 / 设置 / 设备。电脑上是顶部标签，手机上是底部标签栏；记住上次分区（sessionStorage），网址 `#` 仍只用于口令。升级进行中禁止切换分区。
7. 控制：「模式与收听」合并（恢复/暂停收听移到模式卡片）；动作先列 6 个常用，其余收进“更多动作”；方向键注明“行走与转向尚未完整实机验收”。
8. 互动：倒计时、猜谜、称呼与风格、记忆。设置：声音与默认动作、蓝牙、帮助与连接（口令、手机链接、停止并断开）。
9. 设备：供电与提醒 → 低电时暂停新动作 → 姿态与方向 → 姿态动作保护 → 磁方向（加“暂缓 · 未验收”标签）→ 屏幕与摄像头 → 板载硬件 → 无线升级。全部原有功能保留，未删除。
10. 页头狗脸（风格 B）：圆眼、眉毛、狗鼻子、会张合的嘴，垂耳、尾巴、爪子；按固件 `display_service.c` 的顺序映射 9 种状态和 5 种情绪；侧倒、倒置、语音重试会如实提示。
11. 鼻子兼作状态灯（平时白、在听呼吸、出错变黄、休息变暗、断开变灰），点鼻子弹出只读状态卡；点脸其他位置是“摸摸它”。这些都只是页面互动，不发送请求。

所有原有元素 ID（141 个）都保留且没有重复；新增 6 个：`tabs`、`seqCard`、`seqSource`、`seqStatus`、`seqSteps`、`posesMore`。

## 离线 / 模拟测试结果（均为模拟，不代表实机通过）
- 连续动作：本地 3 步、模型 4 步逐步推进；运行中点停止 → cancelled（完成 1 步，剩余 2 步划掉）；finished、dry_run（不标记完成）、invalid、aborted、清空后卡片隐藏，均显示正确。
- 4 个分区切换正常，同一时间只显示一个；恢复/暂停收听在新位置可用；狗脸 12 种状态、点鼻子状态卡（点别处、按 Esc、8 秒后都会收起）正常。
- 电脑宽屏 1280px、安卓窄屏 360px 无横向滚动；浏览器控制台无报错；响应头带设备同款 CSP，没有外部资源。
- 预览图：`docs/previews/desktop-control.jpg`、`desktop-sequence.jpg`、`mobile-control.jpg`、`mobile-sequence.jpg`、`mobile-device.jpg`、`dog-face-states.jpg`、`dog-nose-status-card.jpg`。

## 待实机验证
- 真实连续口令下，`command_sequence` 的 completed 推进节奏与页面显示是否一致；停止后剩余步骤是否立即取消。
- 狗脸表情与设备屏幕是否同步；侧倒/倒置提示是否及时。
- 安卓浏览器：底部标签栏和鼻子点击区（约 41×34px）的触摸手感、安全区留白。
- 页面约 100KB（嵌入固件、未压缩）：编译后核对固件 .bin 与 `ota/state.max_image_bytes` 的余量，以及弱信号下的首屏加载时间。
- `PUBLICATION-MANIFEST.json` 中 `control.html` 的摘要需由主 agent 重新生成。

## 给主 agent 的后端需求（未改协议，仅建议）
- 可选：控制页以 gzip 发送（`Content-Encoding: gzip`），约能把传输量降到三分之一。
- 可选：在 `display/state` 之外，让 `dialog/state` 带上当前屏幕表情名（`expression`/`emotion`），网页狗脸就能和屏幕完全同步，不必按规则推算。
